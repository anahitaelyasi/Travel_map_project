
# تکنولوژی‌ها و ابزارهای مورد استفاده در پروژه نیمراه (Nimrah Tech Stack)

## ۱. مقدمه

در پروژه نیمراه (Nimrah)، از مجموعه‌ای از زبان‌های برنامه‌نویسی، فریم‌ورک‌ها، ابزارها و فناوری‌ها برای توسعه فرانت‌اند، بک‌اند، مدیریت پایگاه داده و ارتباط بین سرویس‌ها استفاده می‌شود.

با توجه به معماری Microservices، بک‌اند پروژه به پنج میکروسرویس مستقل تقسیم شده است. هر سرویس مسئولیت مشخصی دارد و می‌تواند به‌صورت مستقل توسعه داده و اجرا شود.

هدف از انتخاب این تکنولوژی‌ها، ایجاد سیستمی قابل توسعه، مقیاس‌پذیر، قابل نگهداری و مناسب برای مدیریت اطلاعات کاربران، برنامه‌های سفر، گروه‌ها و مکان‌های جغرافیایی است.

---

## ۲. تکنولوژی‌های فرانت‌اند (Frontend Technologies)

فرانت‌اند مسئول نمایش اطلاعات، دریافت ورودی کاربران و ارتباط با APIهای بک‌اند است.

| تکنولوژی | کاربرد |
|---|---|
| React.js | توسعه رابط کاربری و مدیریت کامپوننت‌ها |
| JavaScript | پیاده‌سازی منطق سمت کاربر و تعامل با APIها |
| HTML5 | ساختار صفحات وب |
| CSS3 | طراحی و استایل‌دهی صفحات |
| Tailwind CSS | طراحی سریع و یکپارچه رابط کاربری، در بخش‌هایی که استفاده شود |

### معماری Micro-Frontend

برای تقسیم‌بندی مستقل بخش‌های فرانت‌اند، معماری Micro-Frontend در نظر گرفته شده است.

در این معماری، بخش‌های مختلف رابط کاربری مانند مدیریت کاربران، جستجوی همسفر، گروه‌ها و نقشه می‌توانند به ماژول‌های مستقل تقسیم شوند.

این ساختار امکان توسعه و نگهداری مستقل بخش‌های مختلف فرانت‌اند را فراهم می‌کند.

---

## ۳. تکنولوژی‌های بک‌اند (Backend Technologies)

بک‌اند مسئول اجرای منطق اصلی سیستم، پردازش درخواست‌ها، مدیریت اطلاعات و ارتباط با پایگاه داده است.

| تکنولوژی | کاربرد |
|---|---|
| Python | زبان برنامه‌نویسی بک‌اند |
| FastAPI | توسعه REST APIها و سرویس‌های بک‌اند |
| Pydantic | اعتبارسنجی اطلاعات ورودی و خروجی APIها |
| SQLAlchemy | ارتباط با پایگاه داده و انجام عملیات CRUD |
| Alembic | مدیریت تغییرات ساختار پایگاه داده و Migrationها |
| JWT | احراز هویت و مدیریت دسترسی کاربران |

### معماری Microservices

بک‌اند نیمراه از پنج میکروسرویس مستقل تشکیل شده است:

۱. **User Service:** مدیریت کاربران، احراز هویت، پروفایل و اعلان‌ها.

۲. **Travel Service:** مدیریت برنامه‌های سفر، مسیرهای جایگزین و الگوریتم پیدا کردن همسفر.

۳. **Group Service:** مدیریت گروه‌ها، اعضا، درخواست‌های عضویت و ادغام گروه‌ها.

۴. **Communication Service:** مدیریت چت گروهی، پیام‌ها، تصاویر، فایل‌ها و نظرسنجی‌ها.

۵. **Places Service:** مدیریت مکان‌ها، ایستگاه‌ها، تصاویر مکان‌ها و اطلاعات نقشه.

هر میکروسرویس مسئولیت و پایگاه داده مستقل خود را دارد و ارتباط بین آن‌ها از طریق APIها و پیام‌های رویدادمحور انجام می‌شود.

---

## ۴. تکنولوژی‌های پایگاه داده (Database Technologies)

برای ذخیره‌سازی و مدیریت اطلاعات پروژه از فناوری‌های زیر استفاده می‌شود:

| تکنولوژی | کاربرد |
|---|---|
| PostgreSQL | مدیریت پایگاه داده رابطه‌ای |
| PostGIS | ذخیره‌سازی و پردازش اطلاعات مکانی و جغرافیایی |
| Redis | کش کردن اطلاعات پرتکرار و کاهش درخواست‌های تکراری (اختیاری) |

### PostgreSQL

PostgreSQL پایگاه داده اصلی پروژه است و اطلاعات کاربران، سفرها، گروه‌ها، پیام‌ها و مکان‌ها را مدیریت می‌کند.

با توجه به معماری Microservices، هر میکروسرویس پایگاه داده مستقل خود را مدیریت می‌کند.

### PostGIS

PostGIS افزونه‌ای برای PostgreSQL است که امکان ذخیره‌سازی و پردازش داده‌های جغرافیایی را فراهم می‌کند.

در نیمراه از این فناوری برای موارد زیر استفاده می‌شود:

- ذخیره مختصات جغرافیایی مکان‌ها و ایستگاه‌ها.
- محاسبه فاصله بین نقاط شروع و پایان سفرها.
- جستجوی مکان‌ها و افراد در محدوده جغرافیایی مشخص.
- بررسی میزان شباهت مسیرهای سفر کاربران.

---

## ۵. تکنولوژی‌های ارتباط بین میکروسرویس‌ها (Inter-Service Communication)

برای ارتباط بین سرویس‌های مختلف از دو روش استفاده می‌شود:

| تکنولوژی | کاربرد |
|---|---|
| REST API | ارتباط هم‌زمان بین میکروسرویس‌ها |
| RabbitMQ | ارتباط غیرهم‌زمان و ارسال رویداد بین سرویس‌ها |

### REST API

برای درخواست‌هایی استفاده می‌شود که یک سرویس نیاز دارد از سرویس دیگر اطلاعات دریافت کند یا عملیاتی را درخواست دهد.

### RabbitMQ

RabbitMQ یک Message Broker است که امکان ارسال و دریافت پیام و رویداد بین میکروسرویس‌ها را فراهم می‌کند.

برای مثال، هنگامی که عضوی به یک گروه اضافه می‌شود، Group Service رویداد مربوطه را منتشر می‌کند و سرویس‌های دیگر مانند Communication و Travel می‌توانند آن را دریافت و پردازش کنند.

---

## ۶. تکنولوژی‌های ارتباط لحظه‌ای (Real-Time Communication)

| تکنولوژی | کاربرد |
|---|---|
| WebSocket | ایجاد ارتباط دوطرفه و لحظه‌ای بین کاربران و سرور |

WebSocket در Communication Service برای قابلیت‌هایی مانند موارد زیر استفاده می‌شود:

- ارسال و دریافت لحظه‌ای پیام‌های گروهی.
- نمایش پیام‌های جدید بدون بارگذاری مجدد صفحه.
- اطلاع‌رسانی رویدادهای جدید گروه.
- به‌روزرسانی نتایج نظرسنجی‌ها.

---

## ۷. تکنولوژی‌های ذخیره‌سازی فایل و تصاویر (File Storage)

| تکنولوژی | کاربرد |
|---|---|
| MinIO | ذخیره‌سازی فایل‌ها و تصاویر در فضای Object Storage |
| S3-Compatible Storage | امکان استفاده از فضای ذخیره‌سازی سازگار با پروتکل S3 |

تصاویر و فایل‌های ارسالی کاربران، از جمله تصاویر مکان‌ها و فایل‌های گروهی، مستقیماً در پایگاه داده PostgreSQL ذخیره نمی‌شوند.

فایل‌های اصلی در فضای ذخیره‌سازی جداگانه قرار می‌گیرند و اطلاعاتی مانند نام، نوع، حجم و آدرس ذخیره‌سازی آن‌ها در پایگاه داده ثبت می‌شود.

## ۸. ابزارهای مدیریت و استقرار پروژه (Development & Deployment Tools)

| تکنولوژی | کاربرد |
|---|---|
| Git | مدیریت نسخه‌های کد و تغییرات پروژه |
| GitHub | میزبانی مخزن کد و همکاری اعضای تیم |
| Docker | بسته‌بندی برنامه‌ها و وابستگی‌های هر سرویس |
| Docker Compose | اجرای هم‌زمان میکروسرویس‌ها و زیرساخت‌های موردنیاز در محیط توسعه |
| Kong API Gateway | مدیریت و مسیریابی درخواست‌های ورودی به میکروسرویس‌ها |

### API Gateway

API Gateway نقطه ورود درخواست‌های فرانت‌اند به بک‌اند است.

این ابزار درخواست‌ها را بر اساس مسیر مربوطه به میکروسرویس مناسب هدایت می‌کند و می‌تواند وظایفی مانند مدیریت دسترسی، Rate Limiting و مسیریابی را انجام دهد.
